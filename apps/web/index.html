    01 / The ledger

    What Gideon stops.

    Every rule reads public chain data at the moment you check. If a lookup fails, the answer is “couldn’t check”. It is never “safe”.

    1. 01

      An account that doesn’t exist

      Named accounts are looked up live. A name nobody created can’t receive funds the way you expect.

      not found on testnetBlocked
    2. 02

      A poisoned lookalike

      One or two characters off a saved contact, or a dust sender copying someone in your history.

      northwind-payro11.testnetBlocked
    3. 03

      A transaction hash pasted as an address

      A 64-character hash looks exactly like an implicit account. Gideon looks it up on Tron, Ethereum, Bitcoin and NEAR.

      89a46298…f4126944Blocked
    4. 04

      The wrong network

      A Tron or Bitcoin address, or a .near name while you’re sending on testnet.

      TR7NHqje…otSzgjLj6tBlocked
    5. 05

      The wrong token for an Intents deposit

      A NEAR Intents deposit address made for one token, sent another.

      USDC → USDT depositBlocked
    6. 06

      A token the exchange may not credit

      wNEAR to a deposit address that only credits native NEAR.

      wNEAR → exchangeAttention
    7. 07

      A brand-new account

      Created today or in the last week. Fresh accounts are a common scam tool, so Gideon asks you to look again.

      created todayAttention
    8. 08

      An unused implicit or 0x account

      Valid, but nobody has ever used it on NEAR. Check you have the right one.

      0x94a0abA1…Dca0dd3cd8Attention

    Vermilion means blocked. Nothing else on this site uses it.

    02 / Proof

    Every check leaves a receipt.

    A sha256 over exactly what was checked and what came back. With a signing key it’s also ed25519-signed, so a wallet or agent can prove it checked before it sent.

    • WhatAddress, network, token, destination and amount, as you entered them.
    • AgainstEvery source asked, how long it took, and whether it answered.
    • ResultEach rule’s status, the verdict and the hash. Copy it as JSON from any result page.

    From code

    One call before the send.

    CLI exit codes: 0 safe, 1 look again, 2 blocked, so scripts can stop a send.

    // before the send
import { check } from "@gideon/core"
import { liveSources } from "@gideon/sources"

const r = await check({
  to: "89a46298…f4126944", network: "mainnet",
  destination: "exchange", exchange: "binance"
}, liveSources())
// → verdict "BLOCKED", headline.code "TX_HASH_AS_ACCOUNT"
if (r.verdict !== "SAFE") return r.headline
