01 / How it works

One call before every transfer.

  1. The agent prepares a send

    From a user request, an invoice or another agent: token, amount, recipient.

  2. It asks Gideon

    Format and network, cross-chain hash lookups, account state and age, token contract, Intents deposit status, exchange rules and poisoned lookalikes.

  3. It advises

    Gideon returns the verdict, the reason and a receipt. This page’s demo follows that advice. Gideon can’t stop an agent that sends anyway, and SAFE is not a pass to skip a human when from wasn’t passed.

gideon_check(recipient, network?, amount?, token?, token_contract?, destination?, exchange?, sender?, address_book?, memo?, payee?, chain?, daily_limit?)Runs every Gideon rule. Returns verdict, agent_action (SEND / ASK_HUMAN / DO_NOT_SEND), reasons, fix steps, what couldn’t be checked, and a sha256 receipt (ed25519-signed if you set a key). A daily limit, set here or with GIDEON_DAILY_LIMIT, asks a human when the day’s NEAR would go over it.
gideon_explain(result | same fields as check)Plain-words explanation. Built-in text by default; a NEAR AI model rephrases it only if NEARAI_API_KEY is set. It never changes the verdict, and it refuses a result whose receipt doesn’t match.
gideon_flags(account, network?, registry?)Community reports from the flag registry contract. With no registry set it says COULD_NOT_CHECK, never “no flags”.
gideon_check_transaction(request, or signer, receiver, actions)Before an agent approves a sign link or a transaction someone else built. Same verdicts. DO_NOT_SEND means don’t sign. Gideon still can’t stop an agent that signs anyway.
gideon_account_health(account, network?)Who can act for an account: its keys, risky ones, and unsigned removal links for a human to sign. The agent never removes a key itself.
