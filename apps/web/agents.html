Agent tool · MCP server

Agents send fast. Gideon checks first.

An AI agent that pays copies whatever address it’s given. With Gideon’s MCP server in the loop, the agent calls gideon_check before every send. BLOCKED means don’t send. ATTENTION means ask a human. The reason and the fix come back in plain words.

TodayMCP server gideon-mcp (stdio) with gideon_check, gideon_explain, gideon_flags. Also check() from @gideon/core and the CLI.
ReturnsSAFE, ATTENTION or BLOCKED, with a reason code, a fix and a sha256 receipt (ed25519-signed with a key)
Agent ruleSAFE → send · ATTENTION → ask a human · BLOCKED → do not send. The server tells the agent this when it connects, and every result has an agent_action field.
CustodyNone. Gideon never sees keys and can’t move funds.

01 / HOW IT WORKS

One call before every transfer.

01
Agent prepares a send

From a user request, an invoice or another agent: token, amount, recipient.

02
It asks Gideon

Format and network, cross-chain hash lookups, account state, token contract, Intents deposit status, exchange rules and lookalikes.

03
Sends, or asks

On BLOCKED the agent stops and asks for exactly what’s missing. If a source is down the answer is “couldn’t check”, never “safe”.

gideon_check(recipient, network?, amount?, token?, token_contract?, destination?, exchange?, sender?, address_book?)Runs every Gideon rule. Returns verdict, agent_action (SEND / ASK_HUMAN / DO_NOT_SEND), reasons, fix steps, what couldn’t be checked, and a sha256 receipt (ed25519-signed if you set a key).
gideon_explain(result | same fields as check)Plain-words explanation. Built-in text by default; a NEAR AI model rephrases it only if NEARAI_API_KEY is set. It never changes the verdict, and it refuses a result whose receipt doesn’t match.
gideon_flags(account, network?, registry?)Community reports from the flag registry contract. With no registry set it says COULD_NOT_CHECK, never “no flags”.
