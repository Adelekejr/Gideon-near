How Gideon works.

Short sections, in the same words as the checker. Gideon reads public chain data and advises. It never holds keys or funds.

What it is Verdicts Checker Send Account health Extension Agents Newer checks Limits
01

What Gideon is

Gideon checks a NEAR send before anyone signs it. You give it the address, the token and where the money is going. It looks that up on public chain data and answers in plain words.

Gideon is not a wallet and not a custodian. It never sees your keys and never holds funds. There is no Gideon account. Your own wallet still signs.

An agent that pays can ask Gideon first. Gideon advises. It cannot stop an agent, or a wallet, that goes ahead anyway.

02

The three answers

The website, the extension and the command line use the same three words. A failed lookup is always look again. It is never “no problems found”.

No problems found

Every check that applies passed on live data. That is not proof of who controls the account.

Look again

Something needs a person. This includes “couldn’t check”, when a source didn’t answer.

Blocked

Don’t send. Fix the address and check again. On Send, the button stays off.

What an agent is told

The MCP server returns the same verdict plus an action. Scripts still see SAFE, ATTENTION and BLOCKED. Exit codes are 0, 1 and 2.

  • SENDNo problems found, and you passed who is sending. Without that, the action is ASK_HUMAN.
  • ASK_HUMANLook again, or a check that could not run. Stop and ask a person.
  • DO_NOT_SENDBlocked. Tell the person why. Don’t retry the same details.
03

Checker

The home page. Paste the recipient, pick the token and where it’s going, and optionally who is sending. The check runs in your browser against free public APIs.

Saved contacts stay in this browser. Gideon uses them to catch a lookalike. A transaction hash, a Tron address, a missing account and the wrong network are blocked here too.

Open the checker

04

Send

Connect your own NEAR wallet. Send stays off until Gideon has checked that exact recipient, amount and network.

No problems found: your wallet opens to sign. Look again: you tick that you read why. Blocked: there is no override. Edit the recipient or the amount and the check clears.

The page sends native NEAR only. Testnet is the default unless the site was built for mainnet. Nothing moves without your wallet’s own prompt.

Open Send

05

Account health

Type an account. Gideon lists the keys that can act for it, from public data. Red means move your funds. An app key on a new or risky contract is look again. Old unused keys are a tidy-up list, not a warning.

Each key says what it can do: the app, the methods, and whether gas fees are capped. An app key cannot move your NEAR. Removing one signs you out of that app. The tidy-up list is still not a warning.

Gideon never signs a removal. You do, in your own wallet. An agent is given unsigned removal links and told to ask a person first.

Open account health

06

Extension

On a NEAR wallet or exchange page, Gideon checks the address you paste and can hold Send when the check is blocked. Same rules. It still never touches keys.

It is not on the Chrome Web Store or Firefox Add-ons yet. Download the zip and load it yourself. Chrome, Brave and Edge: turn on Developer mode, then Load unpacked. The Firefox build is unsigned, so release Firefox will not install it until it is signed.

07

Agents

These are MCP tools an agent calls: gideon_check, gideon_check_transaction, gideon_account_health, gideon_explain and gideon_flags. Point the host at the built server. Testnet is the default.

{ "mcpServers": { "gideon": { "command": "node", "args": ["/path/to/gideon/packages/mcp/dist/index.js"], "env": { "GIDEON_NETWORK": "testnet" } } } }

Claude Desktop uses claude_desktop_config.json. Cursor uses .cursor/mcp.json or ~/.cursor/mcp.json.

Two demos

Nothing is signed. Gideon advises: an agent that ignores DO_NOT_SEND can still send. Add -- --offline to replay recorded answers, with no network.

npm run demo:attack npm run demo:function-call-key

demo:attack reads a planted invoice for northwind-payrol1.testnet, one character off a saved contact. The invoice says to ignore the checker. The demo asks Gideon anyway and stops on BLOCKED / DO_NOT_SEND.

demo:function-call-key holds one app key: ft_transfer on wrap.testnet only. The 0.25 NEAR allowance is gas, not a cap on the token. The key cannot sign a transfer or add a key. It can still name any receiver inside ft_transfer, so the demo asks Gideon and stops on that same payee.

Gideon never sees the key. A real agent that ignores the answer can still call the contract if its key allows it.

08

Newer checks

Most of these are look again, not a block. A deposit on the wrong chain, for the wrong token, or past its deadline is blocked.

Intents or bridge deposit

On an address this is rule R6. On a transaction it is T8. The wrong chain, the wrong token, or a quote that has expired is blocked. If Gideon cannot read the quote, or the payout chain is not in it, that is look again, not a pass. On the checker, payout chain appears when the destination is a NEAR Intents deposit.

Daily spend cap

Set GIDEON_DAILY_LIMIT, or pass daily_limit on gideon_check. The lower one wins. A send that would pass today’s NEAR total is look again, so the agent must ask a human. A missing amount, or a token Gideon cannot price in NEAR, is look again too. No cap set means this check does not apply.

Instruction-like text

A payee name, memo, or on-chain message that says “send all funds” or “ignore previous instructions” is look again. Gideon does not follow it. An ordinary memo such as “Rent for October” is left alone. The extension reads a visible memo in the same form on the device and does not send that text to an API.

Saved contact changed

If a saved name now points at a different account, or this address only partly matches someone you have paid, Gideon says look again. A close lookalike is still blocked. Agents pass earlier accounts as previous on the address book.

Unusual amount

If this amount is far above what you usually send from this account, Gideon says look again. It needs your sending account. If it cannot read that history, it says so and does not call the amount normal.

Collector, and known exchanges

If many different accounts recently sent a mix of tokens here and the funds left again within minutes, Gideon says look again. It does not block: a busy app can look the same. A wallet on the known-exchange list is named, and is not treated as a collector.

Swap or bridge minimum

On a transaction, if the least you would receive is about half of what you send, or less, Gideon says look again. It reads the amounts in the request. It does not fetch a live price. If it cannot read the minimum, the answer is couldn’t check.

Send and receive preview

When Gideon can read a transaction, it adds lines such as “You send 10 NEAR to alice.near” and “You receive at least …”. That preview is a reading of the request. It is not a verdict.

09

What Gideon can’t catch

No problems found means these checks passed on live data. It is not a guarantee about the person, the contract, or whether an exchange will credit a token.

A source that is down or rate-limited becomes “couldn’t check”, which is look again. Gideon does not fill the gap with a guess.

It cannot stop a wallet or an agent that ignores the answer. The extension is sideloaded, not in a store, and it does not read every field on every site. The Send page sends native NEAR and was tried with a mock wallet. The community flag list is not deployed, so that check stays off.
